### Aggregate cost view (INFERRED, to be measured by A26)
- Cheapest viable stack (dev): flat/basic cards + Standard scenery + one directional PCF shadow + bloom + final grade pass. Estimated 1-3 s per 360p frame on SwiftShader at 4 vCPU; 60 s clip x 24 fps = 1440 frames = ~0.4-1.2 h. Treatment B adds an outline prepass, ~+50-100 %. SSAO and DOF each +30-80 %.
- Final 1080x1920 = 9x pixels of 360x640: expect 5-20 s/frame in software; 1800 frames = 2.5-10 h per 60 s clip; not feasible in this container for iteration. Needs the local laptop (HD 620 is weak; ANGLE on it likely 2-6 s/frame) or a GPU box. Remotion `--concurrency` over 4 vCPU cuts wall time but SwiftShader is already multi-threaded (INFERRED), so expect <2x.
- Recommendation: allow a "dev quality" flag that drops SSAO, DOF, shadow map to 1024, bloom to half-res. Quality parity risk: DOF/outline widths at 360p differ (see C4).

## 3. Cross-cutting engine risks
- R1 No benchmark: every cost class is INFERRED. First Phase 5 experiment must time one 360p still per feature added (EXP per module).
- R2 Determinism across machines: SwiftShader (cloud) vs Intel/ANGLE (laptop) will differ numerically; hash tests valid only per environment (INFERRED).
- R3 `angle` memory leaks (DOC-2): split long renders into segments of N frames and concatenate with FFmpeg; also helps resumability.
- R4 Asset loading: textures via `useTexture`/`TextureLoader` must be wrapped with `delayRender`/`continueRender` (INFERRED; standard Remotion practice, not covered in DOC-1) and use `staticFile`; mipmap and colour space (`SRGBColorSpace`) must be set explicitly.
- R5 Software WebGL2 limits: MAX_TEXTURE_SIZE 8192 (technical-audit); float render targets/MRT under SwiftShader should work but are slow (INFERRED).
- R6 Remotion licence: Free licence conditions recorded in `research/integration-feasibility.md`; A25 did not re-verify DOC-3 details; director to confirm before commercial use.
- R7 Flow dependency: pose-swap library (A04/A24) depends on separated layers from Flow, not drivable from container (research/integration-feasibility.md).
