# analysis/ — rcpipe: native-frame computational pipeline (A27)

Status: **v0.2.0, validated on synthetic data only** (Phase 2.5 follow-up: schema v2 records, SYN datasets, audio coverage, style/compression study, proxy-vs-native). No real RC30 footage was acquired, decoded or
analysed (Phase 3 not authorised). Every number below is `MEASURED` on synthetic clips generated by
`tests/synth.py`; it says nothing about real footage. Computational output is never visual inspection.

## Usage
```bash
PY=.venv-analysis/bin/python
# one video -> all stages. key = RC30-<nn> (needs knowledge/dataset/MANIFEST.json, else REFUSED, exit 2),
# OUR-<prod>-<render>, or SYN-<x> (synthetic tests only; never reference evidence). --dataset must agree with the key prefix.
$PY analysis/run_pipeline.py PATH/video.mp4 --key RC30-07 --out analysis/data/rcpipe   # git-ignored
# options: --stages probe,decode,motion,shots,color,edges,sharpness,audio,sheets  --proxy-width 540
#          --chunk 150  --sheets-every 30  --exclude-bottom 0.25 (caption band, motion only)  --no-flow
# resume after a crash: simply run the same command again (completed chunks are skipped)
# exact NATIVE frames by frame ID (lossless PNG + JSON sidecar with sha256, pts; --cross-check = bit-exact vs ffmpeg select):
$PY analysis/get_frames.py PATH/video.mp4 --key RC30-07 --frames RC30-07-f000012 RC30-07-f000013 --out private/frames
# tests (generates synthetic media, ~225 s on 4 CPUs, writes <work>/results.md|json):
$PY analysis/tests/run_tests.py --work out/rcpipe-tests
```
Python API: `rcpipe.pipeline.run(input, key, out, proxy_width, chunk, stages, sheets_every, ...)`.

## Stages and outputs (`<out>/<key>/`)
| # | Stage | Module | Output |
|---|---|---|---|
| 1 | ffprobe metadata, per-frame pts, VFR test | `probe.py` | `probe.json` (pts list lives in `frames.csv`) |
| 2 | native decode: ffmpeg rawvideo pipe, `-fps_mode passthrough`, one frame in memory | `decode.py` | `frames.csv` (`frame_id`, `frame_index`, `pts_time`) |
| 3 | reconcile nb_frames / packets / `-count_frames` / pts list / decoded | `reconcile.py` | `reconcile.json` (status ok/mismatch, notes; never silently picks one count) |
| 4 | camera motion + dense flow + residual | `motion.py` | `motion.csv` |
| 5 | shot-boundary candidates | `shots.py` | `shot_features.csv`, `shot_candidates.json` |
| 6-8 | colour/brightness; edges/outlines; sharpness | `stats.py` | `color.csv`, `edges.csv`, `sharpness.csv` |
| 9 | audio: EBU R128, RMS, centroid, bands, dominant freq, onsets | `audio.py` | `audio.json`, `audio_env.csv` (10 ms hop) |
| 10 | computational coverage v2 (one record per run: overall + per-stage ok/uncertain/failed/missing, resolution per stage) | `pipeline.py` | `coverage.jsonl` (`coverage-computational.schema.json` v2) |
| 9b | audio coverage (stream identity, duration vs analysed seconds, missing intervals, stage status, errors) | `audio.py` | `audio.coverage.jsonl` (`coverage-audio.schema.json`); no audio stream -> record with `audio_present: false`, `stream: null`, analysed 0 s, whole duration missing (reason `no audio stream`) |
| 11 | contact sheets (burned-in frame ID + pts; aids only) | `sheets.py` | `sheets/*.png`, `sheets.json` |
| 12 | chunk checkpoints, RSS | `pipeline.py` | `_chunks/`, `run_manifest.json` |
| - | summary measurements | `pipeline.py` | `measurements.json` (list of measurement.schema v2 records: `frames_decoded`, `frames_expected`, `pts_gaps`, `coverage_comp`, stage medians/IQR) |

Every per-frame CSV has `frame_id`, `frame_index`, `status` (`ok`, `uncertain:*`, `error:*`). A frame whose stage raised is
written as an `error:` row and listed in the ledger `missing` with the reason; nothing is silently dropped.

### Motion conventions (analysis-frame pixels, prev -> cur)
`tx,ty` content displacement at the image centre (x right, y down); `scale` content scale per frame (>1 zoom in);
`rot_deg` = atan2(M10,M00), positive = clockwise on screen. Estimators: Shi-Tomasi + pyramidal LK + RANSAC similarity
(primary, on a <= 320 px-wide proxy, results scaled back), `pc_*` whole-frame phase correlation (secondary),
Farneback flow minus global-model flow = residual (`res_*`: mean/p95, active fraction (> 0.7 proxy px), centroid), over
textured pixels only. `confidence`: low if < 12 RANSAC inliers or < 5% textured pixels; medium if inlier fraction < 0.5;
rows at shot/flash/dissolve candidates are forced to `low` (`uncertain:<candidate type>`).

### Shot candidates
Per-pair `hist_luma`, `hist_bgr` (Bhattacharyya), `mad`, `ssim_dist`, `edge_change`, `luma_mean`. Rules
(`shots.detect_candidates`, defaults in signature): flash = luma pulse > 20 levels vs rolling median, <= 6 frames; hard cut
= hist_dist > 0.3 and MAD > 15 and >= 2.5x neighbours and local maximum; gradual = >= 4 consecutive pairs with
hist_dist > max(0.03, 4x median). **Candidates, not semantic labels.**

### Records, datasets, invariants (v0.2.0)
- Keys: `RC30-01..30` (dataset RC30, requires `manifest_sha256` = sha256 of `knowledge/dataset/MANIFEST.json`; the pipeline refuses
  RC30 without the manifest), `OUR-<prod>-<render>` (OUR), `SYN-<id>` (SYN: tool validation only, never reference evidence).
  A key whose prefix contradicts `--dataset` is refused; the dataset-manifest schema stays RC30-only.
- Frame class per stage: `ok`, `uncertain` (measured but flagged, e.g. low texture, at a cut/flash/dissolve), `failed`
  (stage raised, no value), `missing` (frame never decoded / never reached). Overall class = worst stage. Invariant (checked by
  `schema.validate_coverage` and re-checked on every emitted record, the run fails loudly otherwise):
  ok + uncertain + failed + missing == frames_expected, overall and per stage; every failed/missing frame is listed in `missing[]`
  with stage, status and reason; `frames_processed = ok + uncertain`. The first frame of the pair stages (motion, shots) has no
  previous frame: counted `ok` with status `ok:reference_frame_no_previous_pair` (design decision, documented in `notes`).
- Audio coverage: `analyzed_s + sum(missing interval lengths) == duration_s` (+- one 10 ms hop). `duration_s = max(video duration,
  audio end)`; missing intervals are the complement of the decoded audio frames (leading offset, pts gaps / undecodable packets,
  audio ending before the video); decoder errors are captured from ffmpeg and listed in `errors`; undecodable audio is recorded
  (analysed 0 s, stages failed) and never aborts the video analysis. Gaps are zero-filled on the wav time axis
  (`aresample=async`) and flagged `valid=0` in `audio_env.csv`; onsets within 30 ms before/50 ms after a gap are suppressed and listed.
- `analysis_resolution` (mode native|proxy, width, height, native_width, native_height, scaler) per stage in
  `coverage.jsonl: stages[*].analysis_resolution` and per pixel measurement in `method.analysis_resolution`. Colour, edge and
  sharpness stages run at the decoded size (native unless `--proxy-width`); **motion (<= 320 px estimator) and shots (160 px
  features) always work downscaled and are therefore always labelled `proxy`**; the record-level resolution is the finest
  stage that ran (schema rule); per-stage values are in `stages[*].analysis_resolution`. Count metrics (frames, pts, coverage) carry no resolution. Proxy values are never native values
  (`X2.values`: edge width 31.5 native vs 15.5 at 180 px). Use `get_frames.py` for the native pixels behind any row.
- `config_fingerprint` = sha256 of the canonical JSON (sorted keys, no whitespace) of all output-affecting parameters
  (pipeline version, key, dataset, proxy width, every motion/shot/colour/audio parameter incl. defaults); `input_sha256` = sha256 of
  the media bytes. Checkpoints live in `_chunks/<fingerprint[:16]>-<input_sha[:12]>-c<chunk>/`; any other set is discarded.
  Chunk size does not change the fingerprint (outputs are byte-identical) but selects another checkpoint set.

### Resume / memory / disk
Per stage, per chunk (default 150 frames) CSVs are written atomically (tmp + fsync + rename) into the checkpoint set.
Re-running skips finished chunks per stage (the stream is still decoded to supply the previous frame, so a resumed run
costs decode time but no analysis time). If the decoder dies mid-stream the decoded frames are kept and the rest are `missing`
with the error. Frames stream through one pipe (one frame resident); nothing
holds a full-video array. Peak RSS is read from `/proc/self/status` VmHWM and children `ru_maxrss`. Audio is extracted to a
temporary mono 48 kHz float WAV that is deleted after analysis. Contact sheets are 120 px tiles, PNG level 9.
For 1080x1920 sources use `--proxy-width 540` (or similar); the records then say `proxy`.

**Parallax rule (labelled):** with several depth layers the global estimate is ambiguous. Observed lock-on: the far, slowest
layer (largest/longest outlines, most corners), contaminated by the middle layer. Rows with a second coherent motion
(>= 8 RANSAC inliers among the outliers, > 0.5 px from the primary) carry `tx2,ty2,n_inliers2` and status `ok:second_motion`,
confidence `medium`. This flag cannot tell parallax from an independent object (both look like a second motion); inspect
visually before using a camera-speed number from such rows.

## Limitations (read before using numbers)
- Computational, not semantic: candidates, motion and statistics describe pixels; they do not identify shots, characters,
  camera "intent" or style. Stylistic conclusions belong to other specialists with visual inspection.
- Camera/character separation is an estimate: RANSAC assumes the background dominates inliers; a character filling > ~50%
  of textured pixels, flat-colour 2D backgrounds (low texture), motion blur, or parallax layers will bias or flag `low`.
  Residual is meaningful only on textured pixels. Synthetic backgrounds are noise textures; real animated flats are harder.
- Compression: tests use CRF 8-20 H.264; real YouTube re-encodes add blocking/banding. Colour has a -2..-3 level bias
  here; edge width has +-0.5 px quantisation; sharpness values are only comparable at equal resolution.
- Thresholds (shot candidates, 0.7 px residual, 60-level dark ink) were set on synthetic data (shots2 is a true hold-out
  for shot rules only) and are untested on real footage; expect to recalibrate in Phase 3 under a new EXP record.
- Audio loudness is measured on the container's audio as decoded by ffmpeg ebur128 (all channels); short-term values
  need >= 3 s. Onset times resolve ~10 ms (hop); onset_detect is an energy-flux heuristic, not a sound-event label.
- Not implemented/untested: rotation-tagged real videos (handled via probe rotation, untested), HDR/10-bit, multiple
  audio streams (only a:0 is analysed and recorded), interlaced content, ECC alignment, tiled phase-correlation.
- Coverage: `uncertain` frames count as processed (flagged), `failed`/`missing` do not. Frame class = worst stage. A clip with no
  audio stream yields an audio record with `audio_present: false` (schema change by the director).
- Flat colour: motion is anchored on outline corners only (~17% textured pixels); the camera model is accurate on rigid pans/zooms
  even at CRF 45 but (i) parallax gives a layer-dependent blend, (ii) residual-motion fraction/centroid are unreliable under camera
  motion, (iii) the phase-correlation cross-check is unreliable, (iv) shot candidates miss low-histogram-contrast cuts,
  (v) edge width is quantised (1 px == 2 px), (vi) edge-density metrics inflate with compression. All measured on synthetic clips
  that compress far better than real YouTube footage (static flat areas, no grain/gradients/banding).
- Motion and shot features always run downscaled (<= 320 / 160 px) and are labelled `proxy` even for native decodes.

## Reproducibility
Seeds: `numpy.random.default_rng(<fixed per clip>)`, `cv2.setRNGSeed(0)` per frame pair. Versions are stamped in
`run_manifest.json` (this validation: CPython 3.13, numpy 2.5.5, OpenCV 5.1.0, ffmpeg 6.1.1, lock
`requirements-analysis-audio.lock`). Command above; run time 128 s wall on 4 CPUs. Outputs under `out/` or `analysis/data/` are git-ignored.
For real runs the director/A27 copies each `coverage.jsonl` line to
`knowledge/dataset/coverage/computational/<analysis-id>.jsonl` and quotes the input sha256 and `run_manifest.json`.
